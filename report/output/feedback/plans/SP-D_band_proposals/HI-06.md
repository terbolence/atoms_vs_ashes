# Phase 0.6 — Band proposal: HI-06 Military installations (BLOCKED on SP-F)

## 1. Reviewer expectation

- **#120 (Residual register)**: "If the military facility includes ammunition depot or firing polygons" — sub-classification matters.
- **#563 (RO HI-06)**: "Military facility if they do not include amo depot or firing polygons could be much closer without exclusion being activated" — the exclusion zone for non-depot/non-firing-range military sites should be much smaller.
- **#582 (Braila HI-06)**: "Depends on military installation" — same point repeated.

## 2. Current rubric (snapshot)

| Score range | Condition | Descriptor |
| --- | --- | --- |
| [9,10] | `nearest_military_km > 60` | > 60 km. |
| [7,8] | `nearest_military_km >= 30` | 30-60 km. |
| [5,6] | `nearest_military_km >= 15` | 15-30 km (project A5 boundary). |
| [3,4] | `nearest_military_km >= 8` | 8-15 km. |
| [1,2] | `nearest_military_km < 8` | < 8 km. |
| [0,0] | `nearest_military_km < 0.5 and military_type == 'active_exclusion'` | Inside live military exclusion polygon. |

`fail_conditions`: A5 (avoidance_penalty) on `nearest_military_km < 30 AND military_type IN ['firing_range','bombing_range','practice_range']`; A6 on `< 8 km AND military_type == 'ammunition_storage'`.

## 3. Data sanity verdict

Phase 0.5 → `criterion_blocked_until_connector_rework`. `nearest_military_name` 55.1% NULL; `military_type` is sparsely populated and the values used in `fail_conditions` (`'firing_range'`, `'ammunition_storage'`) do not consistently appear in the connector output (the OSM `military=*` tag has its own enum: `base`, `barracks`, `bunker`, `airfield`, `range`, `naval_base`, `ammunition`, `training_area`, etc.).

The fundamental defect is FB-LL-03: the rubric **already has** the right `fail_conditions` design (depot + firing-range get the strict 30 km / 8 km zones; everything else gets distance-only banding) but the data does not honor the classification reliably.

## 4. Diagnosis

Same pattern as HI-01:

1. **FB-LL-03**: distance-only without sub-classification is reviewer-unacceptable. The rubric `fail_conditions` design is correct; the data is the bottleneck.
2. **Connector schema gap**: OSM `military=*` tag is not consistently mapped to the rubric's `military_type` enum.
3. **Reviewer #563 wants explicit relaxation**: "non-depot/non-firing-range military can be much closer without exclusion". The current bands `[5,6]` (15-30 km) and `[3,4]` (8-15 km) treat all military_type the same. After SP-F lands the classification, the bands need to be **type-aware**.
