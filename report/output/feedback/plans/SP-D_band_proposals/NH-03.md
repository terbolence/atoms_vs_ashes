## 3. Data sanity verdict

Phase 0.5 → `data_needs_fix_before_band_edit`. `groundwater_depth_m` is **100% NULL**; `bearing_capacity_kpa` and `depth_to_bedrock_m` also frequently NULL on screening-grade enrichment. `liquefaction_suscept` itself is populated.

## 4. Diagnosis

Two compounding defects:

1. **FB-LL-08 (AND-clause hazard)**: `[9,10]` requires `liquefaction_suscept in ['very_low','none'] AND depth_to_bedrock_m <= 0.6`. Even if susceptibility is `very_low`, the bedrock depth is usually NULL (Phase 0.5: high null fraction), so the AND fails. Same pattern for `[7,8]` which requires `bearing_capacity_kpa > 200`.
2. **`[5,6]` catch-all**: when neither high band fires, the clause `liquefaction_suscept == 'moderate' or ... or (groundwater_depth_m <= 3 and pga_475yr_g < 0.1)` routinely matches because either `moderate` susceptibility is common or the OR-clause `groundwater_depth_m <= 3 AND pga_475yr_g < 0.1` evaluates as `(NULL <= 3) AND (low PGA)` → in the engine's NULL handling this becomes false, but the `'moderate'` branch alone catches anything that's not `low/very_low/very_high`.

For Timelkam (AT, low susceptibility, no bedrock data, no bearing data, low PGA):
- `[9,10]`: requires `very_low/none` + bedrock — NO (susceptibility is `low`).
- `[7,8]`: requires `low` + bearing > 200 — NO (bearing is NULL).
- `[5,6]`: requires `moderate` — NO. Requires `high + remedy` — NO. Requires `gw <= 3 AND pga < 0.1` — `(NULL <= 3) AND ...` = NULL/false → NO.
- → falls through to engine pass-mark default 5.0 with `quality_flag=unscored`.

The reviewer reads "5.0/10" as "low score asserted" (FB-LL-02), when in fact the engine intended "no band matched". FB-LL-01 says: with `low` susceptibility unambiguously documented, the score should be `[7,8]` even when bearing/bedrock data is missing.

## 5. Proposed bands

**Asymmetric NULL treatment** (FB-LL-08 v2): we treat NULL on a **favorable-direction** sub-condition (bedrock, bearing) as not a knock-down (safe-by-absence-of-evidence), but treat NULL on an **unfavorable-direction** sub-condition (`has_remedy`) as conservative no-remedy. This is reviewer-aligned: the absence of mitigation evidence should not let a high-susceptibility site coast through.
