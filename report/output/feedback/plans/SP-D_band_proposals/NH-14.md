# Phase 0.6 — Band proposal: NH-14 Combined hazards

## 1. Reviewer expectation

- **#102 (Timelkam, AT)**: anchor "Combined Hazards (NH-14)". Reviewer: "score prea mic in lipsa unor date care sa-l justifice" — "Score too low in the absence of data to justify it."
- **#575 (Braila, RO)**: anchor "Combined Hazards (NH-14) - score 5.0/10 ... Evidence: values not in measurement tables." Reviewer: "Biased by low scoring where is not justified."

Reviewer's mental model: the combined-hazards index is an **integrative criterion** — when none of the underlying NH criteria are problematic at a site, the combined index should be `[9,10]` ("no material interaction"), not the pass-mark default 5.0.

## 2. Current rubric (snapshot)

`primary_metric: nh14_combined_index` (a categorical enum).

| Score range | Condition | Descriptor |

## 3. Data sanity verdict

Phase 0.5 → `data_needs_fix_before_band_edit`. `combined_hazard_notes` is **100% NULL**, and the audit could not detect whether `nh14_combined_index` is being computed at all (the audit checked the notes column, not the index column directly). It is likely that `nh14_combined_index` is also NULL on most sites, dragging them to the engine pass-mark default 5.0.

## 4. Diagnosis

NH-14 is a **derived criterion** that should be **computed by the engine** from the other NH-* sub-scores at scoring time. If the engine does not compute it (it appears to expect the value to be already present in the DB), the criterion falls through unscored.

Two distinct defects:

1. **Engine-side**: NH-14 should be computed as a **derived criterion** — read the resolved scores of NH-01/03/04/08/09/10/11 for the site and emit `nh14_combined_index` accordingly. The current engine treats it as a regular DB-lookup criterion.
2. **Rubric-side (FB-LL-01)**: even if the engine does not compute NH-14, the rubric should treat NULL `nh14_combined_index` as **favorable** (`'none'` semantically) when **all underlying NH-01/03/04/08/09/10/11 sub-scores are >= 7**. This is the rubric-side bridge until the engine-side fix lands.

## 5. Proposed bands

**Two changes**:

(a) Add an OR-clause to `[9,10]` that fires when `nh14_combined_index IS NULL` AND the site has no underlying NH score below 7 — favorable inference from absence-plus-context.
(b) Add a sentinel for "engine computed; no material interaction" — the cleanest implementation is to make the engine **always compute** NH-14 from the underlying NH scores (deferred to SP-E follow-up).

| Score range | Condition (PROPOSED) | Delta vs current | Descriptor |
| --- | --- | --- | --- |
| [9,10] | `nh14_combined_index == 'none' or (nh14_combined_index is null and nh_min_underlying_score >= 7)` | **ADD** OR-clause for "no underlying hazard" inference | No material interaction (or all underlying NH-* favorable). |
| [7,8] | `nh14_combined_index == 'one_pair_high' or (nh14_combined_index is null and nh_min_underlying_score >= 5 and nh_min_underlying_score < 7)` | same pattern | One pair correlated; or one underlying NH in `[5,6]` and rest favorable. |
| [5,6] | `nh14_combined_index == 'one_pair_moderate' or (nh14_combined_index is null and nh_min_underlying_score >= 3 and nh_min_underlying_score < 5)` | same pattern | One pair at 5-6 OR a single pair at 4-7 OR one underlying NH in `[3,4]`. |
| [3,4] | `nh14_combined_index == 'multiple_moderate' or (nh14_combined_index is null and nh_count_below_5 >= 2)` | same pattern with count of low underlying scores | Multiple moderate hazards interacting unfavourably. |
| [1,2] | `nh14_combined_index == 'severe'` | unchanged | Credible severe integrated risk combinations. |
| [0,0] | `nh14_combined_index == 'e_level'` | unchanged | Combined consequence reaches E-level threshold. |

`nh_min_underlying_score` and `nh_count_below_5` are **derived expressions** — the engine computes them at scoring time from the resolved scores of NH-01/03/04/08/09/10/11 (per the descriptor list in the original `[9,10]` band). This requires an engine change, not just a rubric change.

## 8. Open questions for reviewer

- **Q-NH-14-A**: approve the engine-side derivation of `nh_min_underlying_score` and `nh_count_below_5`? This is a **scoring-engine change** beyond a pure rubric edit. **Default-recommend yes** as it is the only way to make NH-14 deterministic and reproducible.
- **Q-NH-14-B**: should the engine ever compute `nh14_combined_index` itself from the underlying scores (e.g. `'one_pair_high'` if exactly one pair has both >= 7), so the rubric stops needing the OR-clauses? **Default-recommend yes as a Phase-2 follow-up.**

## 9. Hand-off note for SP-D

This proposal **depends on** an engine-side change (SP-E follow-up) that exposes `nh_min_underlying_score` and `nh_count_below_5` to the rubric expression evaluator. Until the engine change lands, the OR-clauses are inert (because the variables are unresolvable) and the existing pass-mark default applies — i.e. landing the rubric edit alone is harmless but useless. **SP-D should land rubric + engine in the same commit**.
