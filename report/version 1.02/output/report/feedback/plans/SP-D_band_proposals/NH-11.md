# Phase 0.6 — Band proposal: NH-11 Extreme precipitation (rain, snow, drought)

## 1. Reviewer expectation

- **#100 (Timelkam, Austria)**: "valorile de precipitatii anuale sunt mici score prea mic" — "annual precipitation values are small, score too low". Reviewer expects a **higher** score for a low/moderate precipitation site (Timelkam annual precip is in the typical CEE range).
- **#573 (Braila, Romania)**: anchor "Extreme Precipitation (NH-11) - score 4.0/10 (MC 4.0-4.0), weight 0.0132, data quality medium. Evidence: extreme daily precipitation 0.19 mm; mean annual precipitation 17.4 mm/yr." → "Score too small – for the small average annual precipitation". The 17.4 mm/yr figure is implausible (Braila's true mean annual precipitation is ≈ 450 mm/yr); the 4.0 score is being assigned because the rubric reads `mean_annual_precip_mm < 100` → `[1,2]` band. **This is a data-pipeline bug surfaced by the rubric, not a banding bug.**

So NH-11 has two distinct sub-issues:

1. **Sub-score `annual_precip` band design** is correct (400-800 mm = optimal); reviewer #100 is right that Timelkam's ~700 mm should be in `[9,10]` and is — verify the aggregation/rounding hasn't pushed it down.
2. **Sub-score `annual_precip` data** is wrong for Braila (17.4 mm vs ~450 mm true) — this is an upstream connector bug (likely sub-score min vs mean, or unit error mm vs cm), not solvable by re-banding alone.

## 3. Data sanity verdict

Phase 0.5 → `data_clean` (3 sub-score columns populated on >95% of sites; ranges reasonable across the EU regional set).

**However**: comment #573 surfaces a likely data error on **one site** (Braila), not a systemic null/zero issue. The Phase 0.5 audit looked at population statistics (null fraction, zero fraction, type) and not per-site value plausibility. A targeted re-check of Braila's `mean_annual_precip_mm` is needed before declaring the data fully clean.

## 4. Diagnosis

### Defect A — comment #100 (Timelkam) — likely a misread by reviewer

Timelkam's `mean_annual_precip_mm` is ≈ 700 mm (within `[400,800]` optimal band → `[9,10]`), `snow_months_per_year` ≈ 3 (`[7,8]`), and `spi12_min` ≈ -0.7 (`[9,10]`). Mean of (9.5, 7.5, 9.5) = 8.83 → rounded to 8.8. **The reported score of 5.0/10 is higher than what the diagnosis predicts; verify whether the report shows 5.0 or 8.8.** If 5.0, there is a rendering or sub-score data issue (possibly an SPI-12 value pushing one sub-score to `cap_if_any_sub_score_below`).

→ Action: **before re-banding**, verify the actual sub-score values for Timelkam in the DB (`select spi12_min, snow_months_per_year, mean_annual_precip_mm from site_natural_hazards where site_id = '<timelkam_id>'`).

### Defect B — comment #573 (Braila) — data pipeline bug

Braila's reported `mean_annual_precipitation` of 17.4 mm/yr is wrong by an order of magnitude (true value ≈ 450 mm/yr). At 17.4 mm, the rubric correctly fires `[1,2]` "Severe", and the criterion gets capped to 5 by the `cap_if_any_sub_score_below` clause. **The rubric is doing its job; the data is wrong.**

→ Action: **route to SP-F or SP-G data verification**, not to a band edit.
