# Phase 0.6 — Band proposal: NH-09 River flooding

## 1. Reviewer expectation

- **#99 (Timelkam, AT)**: anchor "flood zone class: negligible". Reviewer: "flood zone class: negligible?? Score prea mic" — "Flood zone class is negligible — score is too low."

Reviewer's mental model: when the flood-zone classification is `none` / `negligible`, the score should be `[9,10]`. The current rubric instead requires `river_distance_km >= 10` AND/OR `elevation_above_design_flood_m >= 30.5`, which the AT data may not satisfy.

## 3. Data sanity verdict

## 4. Diagnosis

The `[9,10]` and `[7,8]` bands are river-distance OR elevation-margin only — **they never test `flood_zone_class`**. With `river_distance_km` 96.4% NULL on the dataset (the connector populates `flood_zone_class` from a polygon overlay but does not write a numeric river distance), the `[9,10]` band fails for almost every site. The `[5,6]` band is the only one that tests `flood_zone_class IN ['none','low']` — so a site with `flood_zone_class = 'none'` that the reviewer expects in `[9,10]` is dropped to `[5,6]`.

This is the canonical FB-LL-01 + FB-LL-08 pattern: the favourable signal (`flood_zone_class = 'none'`) exists in the data but the rubric does not honor it at the high band.

For Timelkam (AT, `flood_zone_class_500yr = 'negligible'` per reviewer's anchor, `river_distance_km = NULL`, `elevation_above_design_flood_m = NULL`):
- `[9,10]`: NO (river NULL, elevation_margin NULL).
- `[7,8]`: NO.
- `[5,6]`: matches (`flood_zone_class IN ['none','low']` — assuming 'negligible' maps to 'none' in the connector enum) → 5.5.

## 5. Proposed bands
