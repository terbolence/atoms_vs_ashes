## SP-B EPRI weight swap protocol (FB-LL-09 / reviewer #1929454976, #72, #77, #117)

The mechanism for swapping project weights with EPRI (or S&L) values is in place
**and the EPRI numerical values are now landed**. Canonical source:
[`config/epri/weights.yaml`](../../config/epri/weights.yaml), transcribed from
[`docs/expert_siting_criteria_evaluation_matrix.md`](../../docs/expert_siting_criteria_evaluation_matrix.md)
§ Summary table (refresh 2026-04-21), which is itself anchored on:

- **EPRI 3002023910 (2022)** "Advanced Nuclear Technology: Site Selection and
  Evaluation Criteria for New Nuclear Energy Generation Facilities" — mapped in
  [`report/regulations/epri/maps/EPRI-SitingGuide_map.md`](../regulations/epri/maps/EPRI-SitingGuide_map.md).
- **IAEA SSG-35** Tables I-1 / II-1 and §3.8 / §4.x, mapped under
  [`report/regulations/iaea/maps/`](../regulations/iaea/maps/).

Each criterion in `config/scoring_rubrics/*.yaml` now carries `weight_factors:
{baseline: <int>, epri: <int>}` and `weight_basis_source: {baseline: "<project
intent citation>", epri: "<EPRI matrix citation>"}` (see e.g.
[`nh_natural_hazards.yaml`](../../config/scoring_rubrics/nh_natural_hazards.yaml)
NH-01 block). The baseline-vs-EPRI side-by-side delta is generated by
[`src/scripts/build_epri_weights_artefact.py`](../../src/scripts/build_epri_weights_artefact.py)
and stored in
[`audit/post_processing/epri_weights/`](../../audit/post_processing/epri_weights/).
Headline category roll-ups (composite share, 39 ranking criteria after
exclusionary gates fire):

The numerical EPRI weights are now considered **landed**; an S&L (Sargent &
Lundy) or other future basis still requires the corresponding canonical source
document before its column is filled.

**Mechanism (already wired)**:

- Each `Criterion` in `config/scoring_rubrics/<family>.yaml` accepts an optional
  `weight_factors:` map keyed by basis name (`epri`, `s_and_l`, …) and an optional
  `weight_basis_source:` string-to-string map for citations.
- `weight_normalisation(bundle, profile=..., basis="epri")` applied at engine
  construction time normalises only over criteria with `weight_factors[basis]`
  populated, falling back to the legacy `weight_factor` for any criterion lacking the
  basis with a warning.
- The CLI exposes `--weight-basis` on `atoms-vs-ashes score run`. Requesting an unmapped
  basis (e.g. `--weight-basis epri` before any criterion has `weight_factors['epri']`)
  raises `NotImplementedError` rather than silently using the project baseline.
- The `composite_rankings.weight_profile` column already segregates runs; an EPRI rerun
  writes new rows under a distinct `weight_profile` label (e.g. `baseline_epri`) so
  baseline and EPRI scores coexist for diff.

**Swap protocol (executed 2026-05-11; repeat verbatim if EPRI weights are
re-keyed)**:

1. Land or refresh the canonical EPRI source under `config/epri/weights.yaml`
   with per-criterion integer `weight_factor` (1-10) and a `normative_basis`
   citation pointing at the matrix doc / EPRI / SSG-35 paragraph.
2. Run `PYTHONPATH=src python src/scripts/_sp_b_epri_weight_patch.py` to write
   `weight_factors: { baseline: <X>, epri: <Y> }` and
   `weight_basis_source: { baseline: "<...>", epri: "<...>" }` into every
   criterion under `config/scoring_rubrics/<family>.yaml` **and**
   `config/scoring_specs/<family>.yaml` (the patcher is idempotent).
3. Run `pytest tests/scoring/ tests/criterion_spec/ -q
   --ignore=tests/criterion_spec/test_threshold_reset_flow.py` to confirm the
   compiler parity gate still passes (no drift between specs and legacy
   rubrics).
4. Regenerate the side-by-side delta artefact:
   `PYTHONPATH=src python src/scripts/build_epri_weights_artefact.py` — writes
   `audit/post_processing/epri_weights/baseline_vs_epri.{csv,md}` and
   `basis_resolution.json`.
5. Smoke run (no DB writes):
   `atoms-vs-ashes score run --weight-basis epri --weight-profile baseline --help`
   no longer raises `NotImplementedError`. Verified.
6. Full rerun (GUI-only per project policy):
   `atoms-vs-ashes --run-id feedback_v2_epri_<YYYYMMDD> score run --weight-basis epri`.
7. Re-export bundles + regenerate site / country profiles via SP-G; the
   per-bullet `weight X.XXXX (basis: epri)` provenance comes from
   `weight_basis_resolution(bundle, basis='epri')` in the renderer (FB-LL-09).
8. Diff `composite_rankings WHERE weight_profile = 'baseline'` and
   `weight_basis = 'epri'` against the project-baseline rows for the same
   `run_id` window to surface ranking shifts.
